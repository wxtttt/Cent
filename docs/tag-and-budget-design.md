# 胖记 · 标签与预算功能设计定稿

本文件是设计阶段的收口产物，汇总所有已拍板决定。术语以 [`CONTEXT.md`](../CONTEXT.md) 为准，每条「难回头 / 无上下文会困惑 / 有真实权衡」的决定另立 ADR（索引见文末）。**本轮没有改动任何应用代码。**

## 1. 范围

做：标签分普通/特殊两类、月度普通预算 + 可按需添加的特殊预算、分类额度、参与者、账本级预算起始日、成员管理、预算管理页与标签管理页改版。

不做：APK 的「提醒档位 80%/100%」与「接收预算提醒」开关、PWA 图标角标、任何推送后端、自定义标签组、标签自动切币种、历史数据迁移、每条预算独立设起始日。

## 2. 数据模型

统一放在 `GlobalMeta`（随账本 meta 同步到 WebDAV / GitHub / Gitee），不新增 IndexedDB 表、不新增 tidal entry。

```ts
// 标签：删掉 preferCurrency
interface BillTag {
  id: string;
  name: string;
  color: string;
  kind: "normal" | "special";
}

// 成员：id 首次取当前登录 id（WebDAV 即用户名），之后手工新增用 uuid
interface Member {
  id: string;
  name: string;
  active: boolean;   // 软停用，不删除，历史账单仍能显示名字
}

// 月度预算记录：普通与特殊同构
interface Budget {
  id: string;
  kind: "normal" | "special";
  title: string;
  periodStart: number;   // 生成时冻结的时间戳
  periodEnd: number;     // 生成时冻结；过渡周期可被延长
  totalBudget: number;
  categoriesBudget?: { categoryId: string; budget: number }[];
  joiners: string[];     // 空数组 = 不过滤，包含全部成员（含以后新增的）
  tagIds?: string[];     // 仅 special：关联的特殊标签，可多个
  repeatMonthly?: boolean; // 仅 special：是否参与启动补齐的逐月复制
  isTransition?: boolean;  // 过渡周期标记，供 UI 标注
}

interface GlobalMeta {
  budgetStartDay: number; // 1–31，默认 1（自然月）
  members: Member[];
  budgets: Budget[];
  tags: BillTag[];
  // ...原有字段
}
```

删除：`personal[uid].tagGroups`、`BillTagGroup` 类型与 CRUD、`TagGroupSelector`、预设合并逻辑、`Budget.onlyTags` / `excludeTags`、`repeat` / `start` / `end` 旧字段（新模型不再依赖规则现算）。

`Bill` 结构不变；`amount` 已是本位币金额（`ledger/type.ts:50-51`），预算累加直接用它，无需按 `currency.amount` 换算。`creatorId` 指向 `Member.id`。

**归属月份标签**取 `periodStart` 所在年月：例如过渡后 `11/5–12/14` 标 11 月，下一条 `12/15–1/14` 标 12 月。

## 3. 周期与启动补齐

- 周期由账本级 `budgetStartDay` 切分，`[起始日, 次月起始日前一天]`；29–31 日在没有该日的月份取当月最后一天。普通预算与特殊预算共用同一套边界。
- **每条记录自带 `periodStart` / `periodEnd` 快照**（ADR-0006）：全局起始日只用于生成未来记录，不参与已生成记录的展示、统计与达标判定。
- **启动补齐**（App 初始化时）：从最后一条普通预算的 `periodEnd + 1 天` 起，按 `budgetStartDay` 逐月生成到当前周期，额度 / 分类额度 / 参与者复制最近一条；`repeatMonthly = true` 的特殊预算同样逐月复制，未勾选的不复制。**只往前补，不回头重排已有记录**。
- 普通预算每月恰好一条；特殊预算每月可有多条。
- **改起始日**（ADR-0005）固定三步：把进行中记录的 `periodEnd` 延长到新锚点前一天 → 更新 `budgetStartDay` → 下一条记录从新锚点开始。首次设置立即生效，但走同一套延长规则。
- 新锚点一律取**当前周期结束之后的第一个**满足新起始日的日期，避免反向修改时重叠（15 日改 5 日，当前周期 `11/15–12/14` 会延长到 `1/4`，下一条从 `1/5` 开始）。
- 由此产生的**过渡周期**仍是同一条记录，长度可达 40~51 天；额度不按天数折算，界面必须标注「过渡周期」。

## 4. 计账规则

对某个周期内的账单，按以下顺序判定：

1. 按 `periodStart` / `periodEnd` 过滤账单；沿用现有 `budgetEncountered()` 排除收入。
2. `joiners` 为空则不过滤创建者，否则要求 `creatorId ∈ joiners`。
3. **特殊预算**：账单 `tags` 与预算 `tagIds` 有交集即计入。
4. **普通预算**：排除「带有特殊标签、且当月存在关联了该标签的特殊预算」的账单（ADR-0001 互斥）。若当月没有对应特殊预算（或已删除），这笔账单**回落到普通预算**，不从所有预算里蒸发。
5. **分类额度**：沿用 `isSameOrChildCategory`，大类额度覆盖其下所有子类。
6. `budgetTotal = totalBudget` —— **分类额度不参与总额累加（v8 口径）**。分类额度只是普通预算内部的分项上限：设置分类预算时普通预算总额不会加上去，但记一笔账单时支出仍照常累加进普通预算的「已支出」（`budgetEncountered().totalUsed` 不变）。首页 / 统计 / 账本 / 卡片统一走 `budgetTotal`，避免卡片显示 `¥12,300` 而设置行写 `¥5,000`。分类模型本身不改，额度仍各自按 `isSameOrChildCategory` 归集支出。
7. **特殊标签段内单选**：一笔账单最多带一个特殊标签，从源头避免一条账单被两条特殊预算各计一次（删除自定义分组后，这条硬规则要在新选择器里重新实现）。
8. **大卡合计** = 普通预算额度/已用 + 全部特殊预算额度/已用，分别相加后算总比例。普通与特殊共用同一周期，配合孤儿回落，合计不漏账。
9. **首页与统计**按同一预算周期做全口径汇总（ADR-0007），并在标题标明实际周期；互斥只影响预算归属，不影响首页全口径。

## 5. 页面与交互

### 预算管理页

1:1 设计稿：`docs/design/budget-apk-mockup.html`（可编辑源）+ `docs/design/png/design-s1~s5.png`（1080×2340，与 APK `002/003/029.png` 同比例）。字号、字重、边距、行高按 `cruise-all/pages/002.xml` 的原始坐标定标，不靠目测。**砍掉提醒档位与「接收预算提醒」开关**。> 注：上述 PNG 仍是 v2 版式，v4 终态以本节与第 10 节为准。

- **大卡在页面上方**：卡片外左上角是分组小标题「预算周期」，与下方「预算范围」同字号（12px）、同色、同左边距，不落在白卡里。卡内第一行左侧 `‹ YYYY 年 M 月 ›` 切周期（点月份或右侧详细日期都会唤起通用月份滚轮选择器 `DatePicker type="month"`），右侧同一行是 `M/D - M/D` 详细周期，过渡周期在行尾加标记；第二行「全部预算」合计在左，「已支出 ¥X · NN%」在同一行右侧，下方一条总进度条。箭头可点用近黑 `text-ink`，不可点用 `text-ink-tab/40`。
- **一张卡承载全部（v5 定稿）**：预算周期卡只有一张，点「全部预算」把明细展开在**同一张卡内**，不再生成独立小卡。有特殊预算时「全部预算」标题行右侧显示「普通 + {n} 项特殊」（无特殊预算时不显示）；总额 `¥X` 单独占标题下一行，该行最右是「已支出 ¥X · NN%」，下方一条总进度条。
- **行式明细（v8 定稿）**：普通预算、每条特殊预算、每个分类都是同一种行式：「名称 + 额度数值（+ 标签）」在左，「已支出 ¥X · NN%」在右，下方一条细进度条。名称统一灰色 12px、比紧随其右的金额略小（预算金额 15px / 分类金额 13px 主色），金额是视觉主体；分类行缩进。特殊预算的 `#标签` 用 11px 紫色跟在金额后面，不再独占一行。未设置额度的分类金额位置写「未设置」，不算比例、进度条留空槽。
- **两种展开样式 + 三级配色（v8 定稿）**：只有普通预算时，点「全部预算」直接展开分类预算明细（不出现「普通预算」行、不用紫色嵌套容器）；有特殊预算时展开「多种预算」，用左缩 12px + 浅紫底 `bg-[#b18ad4]/[0.07]` + 内描边表达下级，点预算行才展开它的分类。配色：全部预算总条 brand 橙 → 各条普通 / 特殊预算紫 `bg-[#b18ad4]` → 分类明细蓝 `bg-[#6f9fd8]`；超额统一转红。v7 起已去掉左侧竖线与拐角。不使用「本月特殊预算」这类带「本月」的文案。
- **默认展开（v6 定稿）**：当前周期存在多种预算时默认展开多预算、分类明细默认折叠；历史周期默认全部展开（预算行 + 分类明细）。展开状态按周期隔离，周期或预算构成变化时回到默认。
- **设置项在大卡下方，按分组连卡（v7 定稿）**：分组小标题「预算范围」下是一张白卡内连续 **3 行**（月度预算 / 预算起始日 / 计入成员）——分类预算不再单列一行，改为并入「月度预算」抽屉；「特殊预算」下是另一张连卡（各条特殊预算）。行间只有细分隔线、无间隙，只有不同分组之间才留间距。每行结构「主标题 / 副标题 / 右值 / › 箭头」。三行数值一律取所选周期自己的预算记录（含起始日读该周期首日 `dayjs(periodStart).date()`），不读全局配置。
- **添加特殊预算入口（v6 定稿）**：当前周期且没有任何特殊预算时，才显示一张中性虚线添加框（`lucide--circle-plus` + 「添加特殊预算」）；一旦有特殊预算，虚线框整体消失，只保留分组标题右侧的橙色胶囊「新增」按钮。历史周期整个「特殊预算」分组缺省（没有特殊预算时连分组标题都不渲染），有数据时只显示只读连卡。`⊕` 字符全面弃用。
- **所有输入从底部拉起抽屉**，不做行内输入、不做独立编辑页：**月度预算**（一张连卡：第一行「普通预算」总额，下面内嵌它自己的全部一级分类额度，一次确认同时写回 `totalBudget` / `categoriesBudget`）、起始日（7 列 1–31 方格）、计入成员（chip 多选）、特殊预算新建/编辑（标题 / 金额 / 关联特殊标签 / 每月重复 / 成员 / 分类预算 / 删除）。抽屉用项目现成的 `createConfirmProvider(..., { from: "bottom" })`，长表单滚动时「取消 / 确认」常驻底部。分类额度为 0 时输入框留空并显示「未设置」占位，`¥` 隐藏但保留位置，保持整列右对齐。
- **金额输入符号右置（v7 定稿）**：`AmountInput` 让数字输入框占满固定宽度并 `text-right`，`¥` 用 `flex-shrink-0` 固定在最右；位数变化只向左扩展数字，不会把符号往左挤，多行 `¥` 右边缘天然对齐。金额行与分类行共用同一组件（分类行金额区固定 `w-112px`）。
- **未设置预算 / 未设置分类预算（v8 定稿）**：`budgetTotal(b) <= 0` 视为该周期没设预算，右侧写「已支出 ¥X · 未设置预算」，不算 `0%`、不标红、进度条留空槽。分类明细固定列出**所有**一级支出分类（不再只列已配置的）：设了额度的显示额度 + 蓝色进度，没设的金额位置写「未设置」，右侧仍显示该分类已支出但不出百分比、进度条留空槽。账单仍按互斥 / 回落规则计入普通预算总额。完全无预算记录时，启动补齐 `ensureCurrentBudgets()` 会造一条 `totalBudget: 0` 的空普通预算；周期列表来自普通预算记录，因此不存在「可选但无记录」的月份。示例数据 5 个月分别覆盖：未设置预算 / 有总额无分类预算 / 只有普通预算且有分类预算 / 有分类预算+1 条特殊 / 完整多预算。
- **两种展开样式（v8 定稿）**：只有普通预算（无特殊预算）时，点「全部预算」**直接展开分类预算明细**，不出现「普通预算」这一行、不用紫色嵌套容器；有特殊预算时展开「多种预算」（普通 + 各特殊），浅紫底嵌套容器表达下级，点某条才展开它的分类。预算行名称统一灰色 12px，紧跟其右的金额 15px 主色，金额成为视觉主体。
- **计入成员不暴露内部约定（v8 定稿）**：`joiners = []` 表示全部成员（含以后新增的），但设置行副标题与抽屉 hint 都只写「选择计入本预算的成员」，不出现「不选 = 全部成员」。打开抽屉时若内部为空，UI 把全部成员 chip 高亮；保存时若仍是全选，写回空数组（`normalizeJoiners`）。特殊预算抽屉同样处理。
- 右上「编辑」入口已移除；特殊预算的新增 / 编辑 / 删除全部走下方连卡与底部抽屉，不再有整页就地编辑态。
- **历史周期只读（v6 定稿）**：按「覆盖今天的普通预算记录」判断当前周期（不用 `periodContaining(now, startDay)` 现算）。切到其它周期时，在「预算范围」连卡与特殊预算连卡上各叠**一层** `bg-ground/55` 半透明蒙层，行按钮仍 `disabled` 但不再逐行变淡；「仅当前周期可编辑」文字提示已删除（蒙层已足够，避免重复设计）。添加入口按上一节整体缺省。
- **分类预算只列一级支出分类**：抽屉候选为 `categories.filter(c => !c.parent && c.type === "expense")`，子分类不出现。
- **底色铺满**：`PopupLayout` 根与滚动内容区都挂 `bg-ground`，页面底部不留异色空白。
- **字体**：主标题 ~15px、副标题 ~11px、右值 ~14px，字重 400/500；项目 `index.css:552-564` 注明 Windows 中文只有 400/700 两档，`font-semibold`(600) 会渲成 700 粗黑，故全页禁用 600/700。
- 状态表达只用应用内标记：颜色 + 「已超」小角标。不申请通知权限、不调 Badging API、不加后端；Cent 已有的首页「预算还剩 X」与统计「已用 X%」文案保留。

### 标签管理页

对齐 APK `003.png` 的胶囊 tab + 连卡列表：两段「特殊 / 普通」常显、各带小标题与右上「⊕ 新增」，列表是白卡内连续行（彩色圆点 + `#名称` + 箭头）。顶部 tab 决定点「新增」时默认归到哪一段，不做整页切换。点任一标签从底部拉起编辑抽屉（名称 + 类型 chip + 删除）。两段固定不可自定义分组；删掉 `preferCurrency` 及其 i18n 与预设合并；未做拖拽排序。

### 记账页标签选择器

固定两段渲染，特殊段单选；不再渲染分组胶囊，不再有单选/必选/自动切币种。

### 成员管理

新增 / 改名 / 停用（`active` 软停用）。首次导入来源：WebDAV 从账单里出现过的 `creatorId` 反推，GitHub / Gitee 的 `getCollaborators()` 降级为一次性导入源，之后所有端点一律以 `GlobalMeta.members` 为准（ADR-0003）。

## 6. 风险与遗留

- **过渡周期 40~51 天但额度按一个月给**：该月会显得超支，靠 UI 标注缓解；若后续要按天数折算是新决定。
- **跨自然月读数**：`11/5–12/14` 延长后，`12/1–12/14` 的账单算 11 月，用户看「12 月支出」会少一截。时间轴连续的必然代价。
- `totalBudget` 没有币种字段，默认跟 `GlobalMeta.baseCurrency`；换本位币时历史预算数字不会重换算。
- 早期版本把分类额度当「追加」，导致卡片总额与设置行不一致；v8 已改为分项上限不累加。遗留问题变成：分类额度合计可能大于普通预算总额（示例数据 9 月 `3,800 / 4,200`），需要靠文案说明「分项上限、不累加」，不自动裁剪或校验。
- 首页/统计改成周期口径后，统计页分组、导出、同比环比都要跟着改，不能复用 `startOf('month')`。
- 应用未上线、无存量数据（ADR-0004），以上字段可直接改形状，不写迁移代码。

## 8. 实现偏差（2026-11-12 落地时记录）

代码已按本文件实现，以下三处与定稿有偏差，是有意保留而非遗漏：
