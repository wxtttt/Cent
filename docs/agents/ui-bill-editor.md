# 记一笔编辑器、分类、键盘与金额输入

> 由根目录 `AGENTS.md` 拆分而来，属于功能级文档（渐进式披露）。先读 `AGENTS.md` 了解全局约定，改到本模块时再读本文；本模块有新口径 / 新规则时，同步更新 `AGENTS.md` 索引与本文。

## 编辑器域

- **记一笔分类区**（`bill-editor/form.tsx` + `bill-editor/category-sheet.tsx`）：① 一级大类是**纯文字横滑白底行**（`h-10` 行 `bg-panel`，每项 `h-10 min-w-[50px] px-1.5`、无 gap；用户明确「改成白底，选中有字体变色和下面的线就行了」，灰带与选中整块白底已废弃）；行顶到卡片上沿与左右边缘：卡片去掉 `px-3 pt-2.5`、保留 `overflow-hidden rounded-[22px] bg-panel`，实测 `rowTop===cardTop`、`rowLeft===cardLeft`、`rowRight===cardRight`；一级与二级之间**无分隔线**，整卡白色；选中只有**橙字 + 分类名下方横橙条**，未选中 `text-ink-secondary/80`；**横条是单个滑动指示器**（用户要求「下面的小横线要滑过去、左右滑动丝滑」）：滚动内容里 `relative flex h-10 w-max min-w-full` 包裹层放 `absolute bottom-0 left-0 h-[3px] w-6 rounded-t-full bg-brand`，`useLayoutEffect` 量目标项 `offsetLeft + offsetWidth / 2 - 12` 写入 `translateX`，`transition-transform duration-300 ease-[cubic-bezier(0.22,1,0.36,1)]`，横滑时随内容移动、切大类时滑过去，不要改回每项各渲染一条；**要体现一级可以横滑**：项宽 50px（第 6 项半露）+ 右缘 `w-20` 渐变淡出（`linear-gradient(to right, transparent 0%, var(--dp-color-panel) 100%)`，全宽渐变；用户嫌 `w-10`+80% 的淡出「现在看不出来」，已加宽到 80px 且不再提前封顶，二级行的右缘淡出同步 `w-6`→`w-12`）；用户明确「右边有模糊就行了不用右箭头按钮」，**不要叠 `chevron-right` 等箭头**；用 `onScroll` + `syncGroupRowScroll` 维护 `groupRowAtEnd`，滑到底自动隐藏淡出；点大类自动落到该组首个二级，**一级行不放「更多」按钮**；**分类卡片紧凑且二级图标在白色区垂直居中**（用户明确「分类卡片没必要搞这么大」「二级图标要在白色区域的中间」）：现卡片 133px = 一级行 `h-10` 40 + 白色区 93（二级格子 73 + 二级行 `py-2.5` 上下各 10；原 14px 留白被用户指出一级与二级之间显空，收紧后卡片整体变矮、卡片间距不变），卡片不加 `pb`、二级行不加 `mt`，上留白＝下留白严格对称，顶部 `flex-1` spacer 约 15px；**卡片间距按 APK 对比调整**：APK 侧边抽屉相邻卡片间距 44 图像 px ÷2.75 ≈ 16 CSS px、首页概览→总结卡 ≈ 22px，我们原来 12px 偏紧（用户要求「APK 也这样才不用管」），故分类→meta、meta→金额框改 `mt-4` 16px；**金额框→键盘仍是 `mt-3` 12px**（用户早前专门要求「白框和键盘间距改回去」，别动）；`BillCategoryCell` 内边距统一 `p-1.5`，不要给主表单单独放大图标（已废弃 `largeIcon`）；**不要把主表单改成抽屉那种左右分栏/竖栏**（用户已明确回退一次：「保持原来的横向滑动，选中 1 级分类的交互改成抽屉里面的交互」＝只改一级选中态，二级仍横滑且不跨大类）；② 二级分类是一屏 5 个、可左右划的横向行（`[data-sub]`，全量渲染不截断，超过 5 个时右边缘淡出提示；从抽屉选中的二级自动滚入视野），每格宽度 `w-[calc((100%-48px)/5)]`；③ 二级行右边缘固定一个 **24px 小展开按钮**（`bg-brand/10` + `lucide--layout-grid` 图标，常驻不参与滚动，不做成和图标一样大的格子），点它从底部上滑 `showBillCategorySheet` 抽屉：**锚点式左右分区**（用户明确「全部都不需要了，就是自然滑下去滑到某个分类，左边就自动选上」）——右侧是「常用 + 各一级大类」拼成的**一条连续分段列表**，每段 `[data-section-id]` + 5 列图标网格（`gap-x-1`，格子约 58px；用户明确「一行也要 5 个，可以稍微牺牲点大小」，但铺满后要适当放大），**没有「全部」筛选项，也不再按左侧点击把右栏替换成单个大类的网格**；左侧 `w-16` 竖栏只是这些段落的锚点（每项 `h-[52px]` + `gap-0`，选中块上下不留灰缝；用户嫌原来 36px + 6px 太密、又要求「整块区域变色」）；右栏 `onScroll` 以 `grid.top + 16` 为判定线按段顶反查 `activeId`，滚到底强制高亮最后一段，点左栏则 `scrollTo({ top, behavior: "smooth" })` 到对应段并用 `lockScrollSync` 锁 600ms 抑制反向联动（卸载时清 timer）；早期「不按大类分组平铺」「点左侧筛选单组」「切大类 `scrollTo(0)`」三种做法均已废弃：每段一个 `[data-section-title]` 标题（12px 常规 `text-ink-secondary/80` 浅灰组名 + 左右两条等分 `flex-1` 的 `bg-ink-secondary/15` 细线，组名严格居中）+ 该组 5 列图标网格，组间 `mb-3.5`，跳过空的一级大类分组、常用段为空仍保留并显示空态；标题**随内容滚动、不要 sticky**（吸顶会盖住上一组图标，只剩半截名称文字）；分类相关文字统一浅一档：左侧竖栏未选中项、分组标题、`BillCategoryCell` 图标下方名称都用 `text-ink-secondary/80`（原来是 `text-ink-secondary` / `#8a8a93` / 深色 `text-ink` 加粗），名称的 `text-center` 居中不变，共用 cell 会同步影响主表单二级分类名；「常用」是列表第一段（无数据时该段显示 `bill-frequent-empty` 空态，左栏仍保留锚点），每个分段都有组名标题；**不要竖分割线**：内容区去掉左侧 `px-4`；左栏容器 `bg-ground` 与右栏同色，未选中项是 `bg-ground-muted`(#ececec) 灰块、顶到屏幕最左边（`left=0`）；**圆角分区**（用户给参考图要求圆角）：选中项邻接的灰块朝选中侧收 12px 圆角——上邻 `rounded-br-[12px]`、下邻 `rounded-tr-[12px]`，切口露出容器与右栏同色形成弧形过渡；`transition-[color,background-color,border-radius] duration-200` 让圆角随选中移动平滑过渡；选中项 `h-[52px]` 整块 `bg-ground` 与右栏**同色** + 3px 品牌橙竖条 + 橙字（配色用项目自身中性灰 + 品牌橙，不抄参考图的蓝色）；**内容区外层不要 `pb-6`**，右栏 `pt-2 pb-6`，左栏底部灰色由 `min-h-6 flex-1 bg-ground-muted` filler 铺到抽屉底边（末项选中时 filler 同样 `rounded-tr-[12px]`），实测 `railBottom === drawerBottom`；右栏只留 `px-3`，铺满后图标格子从约 52px 放大到 58px；「分类管理」从底部一整行改成**标题栏最左侧齿轮**（`aria-label="分类管理"`），「选择分类」标题用 `absolute inset-x-0 text-center` **居中于抽屉中心**；**右上角关闭 X 已换成 `w-[116px]` 圆角搜索框**（`input[type=search]` + 清空按钮，关抽屉靠点遮罩 / 下拉），抽屉底部不再有管理按钮；齿轮**不再返回 `manage`**，而是直接在抽屉之上叠开 `showCategoryList(edit.type)`（沿用项目已有的多层 Provider 叠放），点「返回」关闭分类管理页后**抽屉仍在原处、滚动与搜索状态都保留**；搜索只按二级分类名 / 英文 id 匹配（**不匹配大类名，用户明确「搜大类名不用管」**），结果在右栏平铺 5 列、左栏不高亮，清空恢复连续分段，搜索态点左栏会先退出搜索再滚到该段；④ 抽屉只返回 `{categoryId}`，一级高亮由 `findGroupOfCategory` 反查同步，`changeType` / `getMatchDefaultCategory` 仍把一级 id 落到二级；⑤ 表单已删除「再记」按钮。分类卡总高度保持两行，金额输入区必须完整可见。

- **记一笔分类区补充规范**（用户逐条确认）：① 一级 chips 选中态与二级分类**同款橙色描边框**（`border-brand bg-[#f6e0d2]`，未选中 `border-transparent`），抽屉筛选 chips 同步；② 一级行首位是「常用」虚拟分组（`FREQUENT_GROUP_ID = "frequent"`，带 `lucide--flame` 小图标）：统计**最近 10 天、同收支类型、按 `categoryId` 出现次数降序**的 top10 二级分类，抽屉左侧锚点首位也是「常用」（对应右侧连续列表的第一段），无数据用 `bill-frequent-empty` 空态；挂载时调一次 `refreshBillList()` 补齐账单（store 首屏只有 200 条且不保证按时间排序），用 ref 防止重复；停在「常用」时 effect 不按所属大类跳走，从抽屉选分类由 `openCategorySheet` 显式 `setActiveGroupId` 同步；③ 备注改成 `remark.tsx` 的 `showRemarkSheet` 底部抽屉（输入框 + 推荐备注 + 取消/确认），主表单只留点击触发按钮，**不要再嵌 `IOSUnscrolledInput` 或自动 Popover**；④ `keyboard.tsx` sheet 变体：公式含运算符时橙色主键从「完成」变「=」，点击先 `press("=")` 结算、再变回「完成」，`+` / `−` 与数字键共用基础样式、激活时用橙色描边框 + 浅橙底（ghost variant 的 `hover:bg-accent` 会盖掉底色，必须同时给 `hover:bg-[#f6e0d2] hover:text-brand`）；⑤ meta 行 `[data-meta-row]` **只统一相邻间距，不要改各选项宽度**（宽度随内容：日历约 170px / 图标 36px）——用户明确纠正过「不是选项一样宽，是选项之间的间距一样宽」，容器 `gap-3`(12px) + `[&>*]:m-0 [&>*]:shrink-0`，chip 统一 `h-9` / `px-3`；**meta 行不再放币种按钮**（见下条）；⑥ **新建账单默认落在「常用」的第一个二级分类**（用户明确「默认应该选中常用的第一个，而不是餐饮的第一个」）：`pickFrequentCategories(bills, groups, type)` 抽成纯函数供初始默认值与 `changeType` 共用，`defaultCategoryRef` + `frequentDefaultAppliedRef` 保证只应用一次、常用数据异步就绪后生效、用户已手动改过 `categoryId` 就不再接管；常用为空时回退到第一个一级大类的首个二级，切换收支类型等于重新进入默认态同样优先常用第一个。**默认应用与「一级高亮按 categoryId 反查同步」必须写在同一个 `useEffect` 里**：拆成两个 effect 会读到同一批次的旧 state，同步 effect 会把刚设的 `FREQUENT_GROUP_ID` 按所属大类覆盖回「餐饮 / 交通」，表现是一级高亮错误、二级行变成该大类的子项。

- **记一笔币种入口**（`bill-editor/currency-sheet.tsx`）：金额前的货币符号本身是 `[data-currency-trigger]` 按钮（符号 + 极淡 `lucide--chevron-down` 提示可点），点它从底部上滑 `showBillCurrencySheet` 抽屉：「快捷币种」（`quickCurrencies`，为空时给设置提示）、「全部币种」（本位币固定首位，2 列网格，选中态同款橙色描边 + 勾）、底部「汇率与货币」→ `showCurrencyList()` 设置页（本位币 / 快捷入口 / 自定义汇率 / 自定义币种）。选中返回 `{currencyId}` 交给表单原有 `changeCurrency()` 做汇率换算，原币金额不变、右下角显示 `≈ ¥ …`；选回本位币即清掉 `currency`。**不要再在 meta 行放 `Select` 或静态「人民币」chip**；`quickCurrencies` 由抽屉内部 `useCurrency()` 获取，表单不再解构。金额白框保持**恒定 64px 一行**、备注垂直居中；`≈ 折算` / 负数提示确定放在**白框内金额行右下角的 10px 角标**（`flex-col items-end self-end`，与备注同排、不另起行），不再放框外。两个已踩的坑：① 金额清空时 `Calculator.Value` 会从 40px 塌到 36px，白框在 60↔64px 跳动 → 金额行必须 `min-h-10`；② 内容区 `flex-1` 会在白框下方留 16px 剩余空白，加键盘 `mt-3` 后白框到键盘看起来有 28px → 内容区首个子元素加 `<div className="min-h-0 flex-1" aria-hidden />` 吸收剩余高度，让白框贴内容区底、间距回到 12px（键盘最后一行仍在屏内）。

- **meta 行日期间距的坑**：`wheel-date-picker.tsx` 的 `DialogTrigger` 里 `<div className="mx-2">{display(current)}</div>` 在 `displayFormatter={() => ""}` 时仍会渲染并白占 16px，导致日期 chip 与后面按钮的视觉间距变 28px（其余都是 12px）；已改成 `displayText` 非空才渲染。改完 `[data-meta-row]` 的可见间距应恒为 `[12,12,12]`。

- **记一笔键盘区与底部安全区**（`bill-editor/form.tsx`）：`PopupLayout` 默认带 `pb-[var(--safe-area-inset-bottom)]`，键盘容器原本还有 `pb-3`，两份叠加会挤掉内容区约 34px，而顶部 spacer 只有 13px 可缩，导致金额白框下半截被键盘盖住（真机约 33px）。现给表单的 `PopupLayout` 传 `className="... pb-0!"`，由键盘容器用 `pb-[max(0.75rem,var(--safe-area-inset-bottom))]` 单独承担（取 max 不叠加）；金额白框另带 `sticky bottom-0 z-10` 兜底，保证任何视口下完整可见。无安全区时间距仍是 16/16/12、金额框↔键盘 12px。

- **金额输入无焦点外框**（用户报「输入价格有个大绿框」）：屏幕键盘每次按键 `press()` 都会脚本 focus 金额 div，命中 `:focus-visible` 后全局焦点环在价格区画一个大外框（APK 无框）。`CalculatorValue`（`components/keyboard.tsx`）挂 `data-no-focus-ring` 抑制外框，焦点指示改由闪烁光标承担：`--animate-caret-blink` 与 `@keyframes caret-blink` 在 `index.css` 定义（此前 `animate-caret-blink` 类名存在但动画从未定义，光标一直不显示）。验证要用脚本 focus 探针（`round17-frame.js`），指针点击不命中 :focus-visible，测不出该框。
