# 车辆记录 / 行车能耗页

> 由根目录 `AGENTS.md` 索引，属于功能级文档（渐进式披露）。先读 `AGENTS.md` 了解全局约定，改到本模块时再读本文；本模块有新口径时同步更新 `AGENTS.md`。
> APK 实机采集方法、adb 工具与截图清单见 `docs/agents/homefull-reference.md`；导航口径见 `docs/agents/navigation.md`；验证脚本见 `docs/agents/verification.md`。

## 范围

- `apps/cent/src/pages/vehicle/index.tsx`：车辆页主体——顶部车辆胶囊、合并主卡、每月花费柱状、记录列表、底栏「记一笔」。
- `apps/cent/src/components/vehicle/page-form.tsx`：`showVehicle()` Provider，`routePath: "/vehicle"`，**r30 起是路由页 + 右侧滑入**，不是全屏 Dialog。
- `apps/cent/src/components/vehicle/`：`index.tsx` 两个底部抽屉 Provider、`forms.tsx` 车辆表单与「记一笔」表单。
- `apps/cent/src/vehicle/`：`types.ts` 领域模型、`stats.ts` 统计纯函数（加满分段、`tripInfo()`、月度分组）。
- `apps/cent/src/hooks/use-vehicle.ts`：只负责读写 `entry: vehicle` 桶与 CRUD。
- `apps/cent/src/components/data-manager/sample-data.ts`：车辆示例数据的**唯一来源**。
- `apps/cent/src/components/profile/index.tsx`：左侧抽屉宫格入口，调 `showVehicle()`（会先收起抽屉）。

## APK 实机口径（2026-11-15 r28，造数据后实测）

**页面骨架**：中性灰白 `#f4f4f4` 底、圆形白返回 + 17px 居中标题「行车能耗」、右上角铅笔（编辑当前车）。车辆切换是**横向橙色胶囊**（选中橙底白字，未选中白底灰字，末尾「+ 添加车辆」），车多时横向溢出，胶囊会被裁。底部固定橙色胶囊「记一笔」。

**空态**（无车）：居中淡灰车插画 + 加粗「还没有添加车辆」+ 两行说明 + 橙色胶囊「添加车辆」。

**主卡**（有车）：白卡 `rounded-2xl`，上半是**平均油耗 `7.00` 大字（橙）+ `L/100km` 小单位** + 「最近一次 7.00 · 均价 ¥7.73/L」灰副标题 + 右侧「+ 添加爱车照片」占位；分隔线下三栏「每公里花费 / 累计里程 / 累计花费」。不足两次加满时大字是 `—`，说明「至少记两次加满，才能算出油耗」。

**图表**：有记录后出现「每月花费」白卡（固定 6 个月标签 6月~11月、橙色圆角柱、柱顶金额标注）；两次加满后多一张「油耗趋势」白卡（同样是**柱状**，不是折线，柱顶数值 + 底部日期）。空月份不画柱。

**记录列表**：卡外小标题「记录」，白卡连卡。每行左侧浅橙圆形图标（加油机 / 充电），主行「加油 40 L」+ 右侧金额（粗），次行「11月14日 · 12,000 km」+ 右侧油耗，第三行小字「距上次加油 500 km」（**橙色**，有数据）/「— 首条记录」或「— 请核对里程」（灰）。里程倒挂时给出「请核对里程」而不是负数。点行打开「编辑记录」抽屉，底部「保存」+ 红字「删除记录」。

**三种能源类型**（这是之前只靠空态推不出来的部分）：

| 类型 | 主卡 | 记录抽屉 | 单位 |
| --- | --- | --- | --- |
| 燃油 | 平均油耗（橙线） | 加油量 L / 加满了 | L/100km |
| 纯电 | 平均电耗（**蓝线**） | 充电量 kWh / 充满了 | kWh/100km |
| 混动 | **左右双栏**：平均油耗 + 平均电耗 | 顶部多一个「加油 / 充电」段控，切换后加油量↔充电量、加满了↔充满了 | 两者都算 |

**记一笔抽屉**（底部圆角、拖拽条、居中标题）：白卡内「日期（可点，三列滚轮：年/月/日，白色胶囊高亮选中行，左 X 右橙圆勾）→ 里程表读数 km → 本次行驶（浅棕卡，自动算与上一条的里程差，首条显示「首条加油记录，将作为下次计算的起点」）→ 金额 元 → 加油量/充电量（自动在下方显示「单价 ¥8.00/L」）→ 加满了/充满了（绿色开关，默认开，说明「两次加满之间才能算出油耗，没加满也照常记」）→ 备注」；第二张白卡「同步记账（绿色开关，默认开，说明「在账本里记一笔支出」）+ 付款账户 现金钱包」；底部全宽橙色胶囊「保存」（必填未填时浅橙禁用）。保存按钮禁用态是浅橙、可用态是饱和橙。

**编辑车辆抽屉**：白卡四行（名称 / 车牌号 / 能源类型段控 / 爱车照片 📷 >）+ 橙色「保存」+ 红字「删除车辆」。

**段控件统一样式**：白底圆角胶囊容器，选中项是白色椭圆 + 轻微阴影 + 黑字，未选中灰字；能源类型三选一、混动加油/充电二选一同款。

## 我们当前实现（r30）

**入口与导航**：车辆页是 `/vehicle` 独立路由页，由 `showVehicle()` 触发 `goPage()`，`.dp-route-from-right` 260ms 从右滑入，返回走 `navigate(-1)`。左侧抽屉宫格点击时先 `onCancel?.()` 收起抽屉，否则抽屉会盖在路由页上。**r29 的全屏弹层方案已废弃**。其它 11 个全屏二级页同口径，见 `docs/agents/navigation.md`；底部抽屉一律不改。

**数据**：示例数据**不自动载入**，`useVehicle()` 只提供 `vehicles` / `records` 与 CRUD，删车时批量清掉孤儿记录；用户要在「数据管理 → 载入示例数据」主动覆盖写入，一次得到 3 台车（小白 / 燃油、小蓝 / 纯电、小闪 / 混动）+ 19 笔含油号与加满标记的记录，走 `entries.vehicle` + `strategy: "overlap"`。

**页面**：顶部胶囊序列「全部 → 每台车 → 添加车辆」，选中橙底白字；「我的车辆」与「能耗概览」合并成一张主卡（车辆信息行 + 能耗大字 + 三栏「每公里花费 / 累计里程 / 累计花费」）；`vehicleFilter` 同时驱动概览、每月花费 6 柱与记录列表，记录行第三行是「距上次… / 首条记录 / 请核对里程」，并带「加满了 / 充满了」标记。底栏固定「记一笔」。

**主卡能耗显示（r30 口径）**：按**筛选范围内有没有能加油 / 能充电的车**决定显示哪几组，跟当前记录里出现过什么能源无关。

- 「全部」且三台车都在 → 平均油耗 + 平均电耗双栏；
- 只筛到燃油车 → 只有平均油耗；只筛到纯电车 → 只有平均电耗；混动车单车 → 双栏；
- 范围内一种都没有就不画那一栏，**不再出现「全部态反而没有电耗」**。
- 大字下方显式写「按上次加满计算 · 日期 里程」锚点，让 `isFull` 的分段作用可见。r30 已删除「添加爱车照片」灰字占位（用户明确不要）。

**统计**：`computeVehicleStats()` 按「加满 / 充满」切段算百公里能耗（`isFull === false` 的记录把加注量累加到下一满箱），旧数据缺 `isFull` 视为加满；`splitConsumption()` 把油 / 电分开算，`lastFullAnchor` 记住分段起点并供主卡展示；`tripInfo()` 给出与上一条同车记录的里程差、首条记录与里程倒挂判定。

**记一笔抽屉（r30 口径）**：

- 顶部类型段控**固定 5 项且「加油 / 充电」始终都在**，不再按当前车的 `energyType` 隐藏。
- **选上面的类型 → 下面车辆行的选项变**：加油列「可加油的车」（燃油 + 混动），充电列「可充电的车」（纯电 + 混动）。**点车辆不改变上面选中的类型**（用户明确要求）。
- 打开时默认带出**上一次加油 / 充电记录**的类型，以及该同类型上一条的油号、加满 / 充满、车辆等有价值选项；保养 / 维修 / 其他不参与默认。
- 字段顺序：日期 → 里程表度数（后置 `km`、灰占位「仪表盘总里程」）→ 本次行驶 → 金额（后置 `¥`）→ 加油量/充电量（自动算单价）→ 油号 92#/95#/98#（仅燃油）→ 备注 → 加满了/充满了开关。
- 日期滚轮 `title` 必须传「日期」，默认是全局 `t("time")` =「时间」（用户反馈「日期点开后为什么标题是时间」的根因）；值手动渲染成 `M月D日`。
- 「本次行驶」的「距上次 X」按**当前选中类型**显示并找上一条同类型记录（不再永远是「距上次充电」），后面的里程数字改**灰色**。
- 选项字号 12→13px / 11→12px、字重 medium / semibold、颜色对比度加深、选中态加一圈细描边，同时把垂直 padding 收 1–2px，**整行高不变**。
- 备注「选填」只由 input 的 placeholder 提供一份，不要在右侧再叠一份灰字。

**删除二次确认**：车辆页删车 / 删记录改用 `createDeleteConfirm()`，与「删除特殊预算」同款居中小圆角白卡（标题 + 描述 + 取消 / 删除两按钮）；不再用 `modal.prompt`。

## 与 APK 实测仍未对齐的部分

改之前先确认用户是否要补齐，别自作主张：

1. 「油耗趋势」独立柱状卡（我们只有每月花费）。
2. 「同步记账 / 付款账户」的真实写账本逻辑，涉及 bill entry 与账户体系，改动面较大。
3. 日期滚轮复用全局 `DatePicker`（datetime-local 5 列），APK 是年/月/日 3 列；标题文案 r30 已对齐为「日期」。
4. 补能类型用 5 类记录段控覆盖，APK 混动是「加油 / 充电」二选一段控；语义接近、版式不同。
5. 纯电主卡用 `kWh/100km` 单位区分，APK 额外有一条蓝色能耗线。
6. APK 纯电说明文案有个 bug：「充满了」下面仍写「两次加满之间才能算出油耗」，别照抄，写电耗。

## 已知约束 / 踩坑

- `components/vehicle/index.tsx` 的 `dialogTitle` 是无障碍标签，曾硬编码英文；**应用无英文名**，已改「车辆」/「车辆记录」。
- **日期后面的 `L`**：`DatePicker` / `WheelDatePicker` 默认 `displayFormatter` 是 dayjs 的 `"L"`，项目没加载 `localizedFormat` 插件时 `L` 会作为字面量显示。车辆记录抽屉必须传 `displayFormatter={() => ""}` 并自己渲染日期文本；不要为此改全局日期组件，其它调用点依赖默认行为。
- **备注「选填」只出现一次**：由右对齐 `input` 的 placeholder 提供。验证脚本读 `input.placeholder`，`placeholder` 不进 `innerText`。
- 「全部」态打开记一笔时默认车来自上一次同类型记录（可能不是燃油车），断言「燃油车不出现充电」前必须先显式点「小白」并确认顶部类型是「加油」。
- 车辆卡横向滚动区是 `flex min-h-0 flex-1 flex-col overflow-y-auto` 父容器的 flex item，必须加 `flex-shrink-0`，否则长页面会把它压成 0 高（WebKit 实测）。
- 三栏指标 label 用 `truncate`：长文案会被截断，单位放在 value 后面。
- 语言键集中在 zh/en 的 `vehicle-*` 段；新增键用独立 `.py` 脚本追加并 `json.load` 校验，脚本必须 `write_bytes()` 保持 LF（`write_text` 在 Windows 会转成 CRLF 造成整文件 diff）。页面回归必须查 `document.body.innerText` 里有没有 `vehicle-[a-z-]+` 泄漏。
- `createConfirmProvider` 只透传 `edit / onCancel / onConfirm`，抽屉内挂不上 `onDelete`；删除统一在页面用 `createDeleteConfirm()` 二次确认。
- **5173 是 `dist` 预览不是 dev server**：改完源码必须重新 `vite build --no-emptyOutDir` 才会被验证脚本看到；曾因为漏重建，连续两轮双引擎都跑在旧 bundle 上，误判「静默 catch 没生效」。
- **取消 Promise**：从抽屉导航到路由页会触发「manually cancelled」的 reject，`confirm/state.ts` 与 `confirm/index.tsx` 已在源头静默 catch，`ProfileAvatar` 的 `showProfile()` 调用点也补了 `.catch(() => {})`；否则浏览器报 `Unhandled Promise Rejection`。
