# 月度预算记录自带周期边界快照

每条月度预算记录在生成时写入 `periodStart` / `periodEnd` 并冻结；账本级的 `budgetStartDay` 只用来生成**未来**记录，不参与任何已生成记录的展示、统计与达标判定。

## Status

Accepted

## Considered Options

- **由全局起始日实时推算周期**：否决 —— `budget/detail-form.tsx:184-215` 会遍历所有历史周期逐个重算达标与预算率；改一次起始日，过去所有月份的结论会整体改写。这正是「单条规则自动重复、历史靠现算」被否决的同一个病。
- **存起始日变更历史 `{effectiveFrom, startDay}[]`**：否决 —— 启动补齐发生在变更之前，历史记录在改设置时已经生成且冻结；补齐只往前补、不回头重排，用不上变更历史。
- **记录自带边界快照 + 全局值只管未来**：采用。

## Consequences

- 记录必须能表达非自然月边界：过渡周期可达 40~51 天，且 29–31 日在短月回退月末，周期长度本就不固定。
- 改起始日固定三步：把进行中记录的 `periodEnd` 延长到新锚点前一天 → 更新 `budgetStartDay` → 下一条记录从新锚点开始。已结束的记录一律不动。
- 启动补齐从最后一条记录的 `periodEnd + 1 天` 起、按 `budgetStartDay` 逐月生成到当前；即使改完设置后长期不打开 App，补出的月份也按新锚点，符合 ADR-0005 的「变更自下月生效」。
- 详情页与统计一律读记录自身的边界，禁止再用 `budgetRange()` 从全局值反推历史周期。
- 过渡周期额度不按天数折算，但界面必须标注；否则用户会把 40~51 天的支出误读成「这个月突然超支」。
